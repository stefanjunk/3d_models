# Anycubic Slicer Next CLI

## Supported role

Use `slice-anycubic-next` for local, headless FDM export with an exact Anycubic printer/process/filament profile set or with an already-authored 3MF project. The adapter creates no cloud task and implements no printer upload or print-start action.

Anycubic describes Slicer Next as OrcaSlicer-based and publishes its source under AGPL-3.0. The manufacturer download page currently offers a Linux build for Ubuntu 24.04 only:

- https://www.anycubic.com/slicerNextDownload
- https://github.com/ANYCUBIC-3D/AnycubicSlicerNext

Treat another Linux distribution as locally observed compatibility, not vendor support. Record the exact executable version and hash on every release run.

## Exact-profile mesh slicing

```bash
python3 "$FDM_VALIDATION_SKILL/scripts/fdm_ci.py" slice-anycubic-next \
  model.stl build/slice-anycubic-next-r1 \
  --machine-profile "profiles/Anycubic Kobra 3 Max 0.4 nozzle.json" \
  --process-profile "profiles/0.20mm Standard @Anycubic Kobra 3 Max 0.4 nozzle.json" \
  --filament-profile "profiles/Anycubic PLA @Anycubic Kobra 3 Max 0.4 nozzle.json" \
  --json-out reports/slice-anycubic-next-r1.json
```

For STL/OBJ, the complete profile set is mandatory. The tested CLI treats `--load-defaultfila` as a boolean switch; appending `1` makes that value an input filename and fails the slice. The adapter encodes the correct flag form.

## Authored 3MF projects

```bash
python3 "$FDM_VALIDATION_SKILL/scripts/fdm_ci.py" slice-anycubic-next \
  authored-project.3mf build/slice-anycubic-next-3mf \
  --json-out reports/slice-anycubic-next-3mf.json
```

With no external profiles, the command uses the profiles and plate configuration embedded in the 3MF. If any external profile is supplied, supply the full machine/process/filament set. Do not rearrange an authored 3MF in the headless release run.

For multicolor work, author or correct painting and ACE slot mapping in the GUI, save the authoritative destination-slicer 3MF, then use the CLI only for batch export/validation. Inspect the final color/tool view and wipe tower in the GUI; a successful headless export does not prove that physical slots, purge, or color boundaries are correct.

## Evidence and reproducibility

The adapter:

- uses a temporary working directory, temporary XDG configuration/cache/data directories, and an isolated slicer datadir so native side files cannot pollute the project;
- refuses an existing output directory instead of overwriting prior evidence;
- records source, executable, and profile hashes;
- requires CLI version discovery, process exit 0, native `result.json` success, and non-empty G-code;
- parses every generated G-code with `analyze-gcode`.

In the validated 1.3.9.4 Linux run, two otherwise identical simple Kobra 3 Max STL slices differed only in the `generated by AnycubicSlicerNext ... on ...` wall-clock header. Preserve each exact G-code hash. This observation is limited to that simple STL; it is not a general determinism guarantee.

A repeated support-bearing 3MF slice also varied after removing the timestamp and progress metadata: nine diagnostic diff hunks changed path segmentation or ordering, positive extrusion differed by about 0.8 mm, travel by about 56.8 mm, and the normal-mode estimate by 1 s. Therefore, compare parsed metrics against explicitly approved tolerances and inspect diagnostic path diffs when reproducibility matters. Never normalize or modify the manufacturing G-code in place, and never treat a normalized hash as the accepted manufacturing artifact.

An authored 3MF test also exposed an Anycubic 1.3.9.4 metadata inconsistency: 94 executable `;LAYER_CHANGE` markers and the header agreed, while the footer reported 95 layers. The analyzer uses the executable markers plus header for the primary count and emits a non-blocking `layer-summary-consistency` review item for the conflicting footer. Keep this warning visible; do not reinterpret it as an extra executable layer.

## Tested scope and boundary

Observed once on 2026-08-27:

- host: Manjaro Linux x86-64;
- Anycubic Slicer Next internal version: 1.3.9.4;
- printer profile: Anycubic Kobra 3 Max, 0.4 mm nozzle;
- process: bundled 0.20 mm Standard profile;
- filament: bundled Anycubic PLA profile;
- model: bundled Orca tolerance test STL;
- result: exit 0, native success, one G-code, 32 recognized/declared layers, normal-mode estimate 602 s;
- simple-STL repeat: native result and timestamp-normalized G-code identical; raw G-code differed only by generation timestamp;
- support-bearing-3MF repeat: native success repeated, but path segmentation/order and small aggregate metrics also varied.

This proves local CLI viability in that software/profile scope. It does not qualify print quality, machine firmware compatibility, material behavior, supports, seams, multicolor purge, or physical safety.
